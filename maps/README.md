# maps/ 目录说明

> **注意：当前默认模式是 `sift`（见 config.json 的 `matcher_mode`）。**
> SIFT 模式直接索引根目录下的完整地图，**`maps/door/` 不参与识别**。
> 下面这套「门裁剪图 + 同名配对」的规则，只有把 `matcher_mode` 改成 `template`
> 时才适用；`maps/door/` 里那批裁剪图现在可以不管它。

识别和显示是两件事，它们通过**同名**配对。

| 放在哪里 | 用途 | 要求 |
|---|---|---|
| `maps/door/` | **识别**：门区域裁剪图 | 严格按游戏里"门"那一小块原样裁剪；宽高比要接近 `config.json` 里 `door_coords` 的 583:300 ≈ 1.94 |
| `maps/full/` | **显示**：完整地图 | 尺寸任意，命中后悬浮窗显示这一张 |
| `maps/`（根目录） | 旧结构兼容位 | 存在同名 door 图 → 只当"显示用整图"；不存在 → 仍按旧逻辑当模板（程序自己按比例从整图里抠门区域） |

## 推荐结构

```
maps/
  door/
    map1.jpg     ← 门区域裁剪图（只用于识别）
    map2.jpg
  full/
    map1.jpg     ← 完整地图（只用于显示）
    map2.jpg
```

两个文件的**主文件名必须相同**（`map1` ↔ `map1`），扩展名可以不同（`map1.png` ↔ `map1.jpg` 也能配上）。

## 为什么门裁剪图的宽高比很重要

不管原图多大，程序都会先统一缩放到 128×128，再做灰度比对。如果裁出来的门图宽高比不是 1.94，缩放时画面会被压扁，形状和屏幕截图那一侧对不上，识别精度就会掉。

程序会对偏差超过 **15%** 的门模板打一条 WARNING 日志（`MapMatcher_Debug.log`），看到就用截图工具重新按门区域原样裁一次。

## 尺寸不统一没关系

门裁剪图的像素尺寸可以各不相同——它们都会被归一化到 128×128，所以不需要跟 `door_coords` 的像素值一致，只要**宽高比**一致。

## 找不到同名整图会怎样

退化为直接显示那张门裁剪图本身。程序能跑，但你看到的只是一小块，看不到整张地图。

## 新加了地图不想重启

右键托盘图标 → **重新加载地图模板**。

## 关于现有的 map1~map10.jpg

它们目前是按**旧结构**当模板用的：程序按 `door_coords` 的比例从每张整图里抠出门区域来识别。

你提到每张图的像素并不相同——如果它们不是"同一视野的不同分辨率"，而是各自不同取景的整图，那按比例抠门区域就未必抠在同一块画面上，识别会不稳。这种情况下建议改成新结构：

1. 进游戏，在每张地图上把"门"那块区域截出来 → 存进 `maps/door/`，命名为 `map1.jpg` ... `map10.jpg`；
2. 原来的 `maps/map1.jpg` ... `map10.jpg` **留在原地别动**，它们会被自动当作同名门模板的显示整图。

改完右键托盘 → 重新加载地图模板即可，不用重启。
